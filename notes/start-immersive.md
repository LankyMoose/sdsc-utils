# Start immersive mode

**Status:** do-not-regress. **When to read:** immersive cover, reopen chord, controllers surface. Index: [README.md](README.md).

Start opens directly as a borderless primary-monitor cover. The reopen chord is fixed **PS** (Guide) and opens Start when closed; while open it is swallowed (no-op). Circle/Escape closes Start (`Close`) after unwinding modals/drawer/surface. Successful launch closes Start so a topmost cover cannot sit above the game.

Enter ceremony: open paints the cover window under a solid top veil; the veil lifts (wall-clock `ENTER_REVEAL_MS`, no per-frame cap — a stall jumps time-correctly along the curve instead of stretching the phase) once splash art syncs (selected backdrop + strip heroes) or the 3s art-hold timeout fires, whichever comes first. Cached art paints opaque under the veil (new-window atlas uploads during blackout — reopen/warm hit, no ambient flash); uncached waits, then ease-in-out ambient → splash after the veil (dim tracks opacity). A `paint gap` witness in the Start view logs repaints stalled >250ms mid-ceremony — the render/present side, never the state machine. Input edges conflate to latest-wins per poll (readings are absolute state), so a saturated loop recovers in one update instead of a 128-deep backlog spree. Any phase completing past spec + 1000ms logs a `phase overrun` witness (ticks starved, not logic slow). Cold process-first open (`cold_load_active`) lifts onto ambient + island + footer with the games strip hidden; a bottom-right **chrome status rail** stacks background jobs (Preparing / Steam / future sources). New jobs slide in from the bottom; finished chips stay **Success** and shift upward. When every chip is Success, a short hold then **staggered slide-right** clears the rail (bottom-first). Art-ready marks Preparing success, fades the games list (`GAMES_LIST_FADE_MS`) with ambient→splash, and immediately kicks Steam so both can stack. Must not re-black the chrome. Boot seeds Steam metadata from `%APPDATA%/<pkg>/steam_library.json` when present. Cache-miss kicks a live scan during cold so art can resolve; cache-hit shows Preparing then kicks Steam on art-ready. Live Steam scan/refresh runs for at least 2s (`STEAM_SCAN_MIN_MS`) so the BR scan chrome stays readable. Status chips slide In (`CHROME_STATUS_IN_MS`) into a growing BR clip; Success holds on the rail until the batch is done, then ExitRight (`CHROME_STATUS_EXIT_MS`) with stagger (`CHROME_STATUS_STAGGER_MS`) after `CHROME_STATUS_SUCCESS_HOLD_MS` + `CHROME_STATUS_STEP_HOLD_MS`. Warm reopen keeps the solid enter veil + cached opaque snap. Art-hold timeout 3s. A UI stall cannot skip the start of the enter curve (32ms/frame cap). Art uses a **single-flight** `start-art-worker` thread (latest-wins mailbox): UI posts one `ArtJob` per selection; at most one decode runs at a time. Pins ±10 around selection (linear window); unpinned entries stay until per-tier LRU caps. Order: selected cover → selected hero/list → visible ±2 strip → prefetch ring. Events: `StartArtEvent` (`SelectedReady` / `NearReady` / `JobDone`). List/hero/backdrop peeks are live (no catalog rebuild on warm). Splash art keeps a **continuous ken-burns** pan/zoom (burn-in drift) while held; title changes use cover-crossfade (solid outgoing underlay at **frozen ken-burns scale** + incoming fade) so ambient never bleeds and the old splash does not zoom-snap. A soft rectangular edge vignette sits over atmosphere/splash only (under strip / island / footer). The controllers island is top-right (same glass as footer hints): SELECT glyph, separator, rings-only strip; opening darkens the stage and reveals the island footer (see Controllers surface). The island uses Left/Right (dpad, stick, arrow keys). Strip Up/Down gated while `strip_anim` is active. Game/controller lists are pad-only (no mouse press/hover); edit actions stay clickable. Disconnect membership uses the same hot-path silence drop + `ServiceMessage::Controllers` (island rows + composite toast).

**Same-press open:** open and the swallowed while-open chord share the reopen chord. After `OpenStart`, a [`ChordReleaseGate`](../src/domain/gesture.rs) keeps the sticky hold latched until the chord is continuously absent for 64ms (longer than one HID wake / bounce). A one-sample gap does not clear the latch or disarm detectors. Shell `consume_reopen_gesture_chord` must not `reset` on Missing snapshot (client mode has no local HID snapshot). Duplicate `OpenStart` while Start is already visible re-arms the latch.

**Immersive idle / sleep:** while open (not during the enter ceremony), a shared activity stamp (mouse move/click/wheel, keyboard Start keys, non-resting pad) drives two overlay phases on top of chrome via `theme::immersive_dim` (ease-in-out ~0.45s, separate from enter/exit veils). Prefs (Settings → Start screen labels Idle/Sleep): `start_screen_inactive_secs` (default 30; steps 5s/15s/30s/1–3/5/10m), `start_screen_sleep_secs` (default 120; steps 1–3/5m then 5m gaps to 60m; always ≥ one sleep breakpoint ahead of idle), `start_screen_inactive_dim_percent` (default 50). After idle timeout → dim to that percent (**Idle**); after sleep timeout → full black (**Sleep**). Any activity targets **Active** (clear). Cursor hide (2s) shares the same activity stamp but stays independent. **Pad while Sleep / sleep-wake:** no nav/launch/surface/cancel/haptics/sounds — non-resting pad may only start wake; gating lifts after Active + dim transition complete, then `pad_nav.prepare_on_open(false)` so held controls must rest. Idle wake may still apply the press. Keyboard/mouse can wake; only pad is hard-gated. Pure helpers: [`src/ui/start/idle.rs`](../src/ui/start/idle.rs).

**Start settings (Options):** DualSense Options toggles an in-window Start Screen settings surface ([`src/ui/start/settings.rs`](../src/ui/start/settings.rs)): full-height right `WidthReveal` drawer above stage/island/footer (separate from the controllers surface); idle/sleep veil stays above the drawer.

**Controllers surface (Create/Select):** DualSense Create toggles the controllers surface (the opposite of Options/START → settings): top-right horizontal island — SELECT glyph first, separator, rings-only strip (no titles, no pill); opening darkens the stage (`dock_stage_dim`) and reveals the island footer (selected-row Identify/Power-off + Connected/All + Back) via a culled height reveal. Circle/Back collapses the open surface first. L2/R2 are inert; Left/Right move the open surface's selection or scroll the horizontal games strip.

**Start settings (Options) continued:** Prefs match Configure → Start Screen except **Enabled** (Configure-only). Pad: Up/Down focus rows, Left/Right nudge sliders (and toggles: left=off, right=on), Cross toggle/activate, Circle/Options close. Esc matches Circle: with a dropdown open it closes the menu only, otherwise the whole surface. Reopen chord is not configurable (always PS). Overlay priority: settings → manual_add → replace_confirm → edit → controllers collapse → close. Main Start footer stays on browse controls (idle while settings owns press). **Hint press ownership:** only the active surface lights face/Options/Create glyphs — `HintPressOwner` in [`view.rs`](../src/ui/start/view.rs). Options glyph is a regular-weight monospace `START` capsule sized to the face-ring idle diameter.

**Debug ambience tuning (non-release only):** the drawer ends with a "tune ambience" action row opening a centered tuning panel ([`src/ui/start/ambient_tune.rs`](../src/ui/start/ambient_tune.rs)) with the same 12 ambient sliders as Diagnostics. Opening closes the drawer. While open, splash art is hidden (stage keeps its vignette so the layer matches the standalone preview window) and game nav is parked (`overlay_blocking` covers the message-driven paths; pad nav routes to the panel: Up/Down focus with wrap, Left/Right nudge, Cross Reset/Done, Circle back to drawer, Options close without drawer). R3 toggles all on-screen elements including the panel for a clean preview (release-latched; pad-only, no NavAction); toasts composite off while hidden. The panel never survives close. Cold-start art order: boot may seed Steam metadata from `steam_library.json`; live scan on `StartOpened` refreshes and rewrites the cache. When metadata is available, UI `request_start_art` pins ±10 and submits one worker job; selected **hero/list** first (strip paints immediately), then selected **backdrop** (`SelectedReady` arms splash), then ±2 strip heroes/list (`NearReady`), then near backdrops, then prefetch heroes before backdrops (`JobDone`). Newer selections replace the pending job (mailbox drain between paths); a superseded job is **kept** and run next (close→reopen must not drop the reopen job). Start close: bump gen + `cancel_jobs` (cache kept for reopen). **Process Exit blank slate:** drop Start row Handles + immersive session; `art_worker::shutdown` wipes caches (icons / shell extracts / SVG rasters / ambient+wgpu diag) **before and after** join (clear-epoch rejects late inserts); service Quit waits ~2.5s for shell Exit before kill. **Horizontal strip art anchoring + in-slot titles:** the ART is the vertical anchor, not the slot box — `vstrip::slot_y_offset_h` puts the strip top at the selected art's top so every capsule shares one centerline and in-slot titles hang below their art. Horizontal arc (`vstrip::arc_offset_y`, `H_ARC_PX` per distance unit) then sags neighbors DOWNWARD (+Y, cover-flow sag, keeps clock clearance) on top of that anchor — final layout y = `slot_y_offset_h + arc_offset_y`; flip `H_ARC_SIGN` to `-1.0` to arc upward instead. Center-*box* placement (the old behavior, plus a downward `arc_offset_x` lean) floated neighbor art half its in-slot text reserve **above** the selection. **Every** horizontal slot — the selection included — is art plus the same in-slot title/meta (`strip_slot_stacked`), so titles animate with their card; the separate full-width selected-title layer and its crossfade clock (`TitleAnim`, `title_crossfade_visual`, `title_crossfade_*`, `TITLE_DRIFT_PX`, `H_SELECTED_TITLE_RESERVE`, `H_STRIP_TO_TITLE_GAP`, `H_ART_CENTER_OFFSET`) are gone. Consequence: `metrics_for_width` sizes the strip as exactly the selection's box (`selected_art + h_text_budget`) and `horizontal_block_lead` takes the in-slot text height where it used to take the title-layer offset. Outer peeks (`|offset| >= 2`) render their title + meta at their own art-width wrap (`vstrip::h_outer_wrap_width`) in smaller 18px type (`H_TITLE_OUTER_SIZE`) — same-wrap neighbor titles are wider than the 1→2 stride, so a d=2 title at neighbor width would overlap its neighbor ~21px (test `outer_peek_titles_would_overlap_at_neighbor_wrap`), but own-art widths fit every outward stride with the edge gap to spare (test `outer_wrap_fits_stride_at_every_step`). The wrap is keyed on the stable integer offset so breaks never reflow mid-scroll; a heavy outer stack (3-line 18px title + 2-line meta + badge ≈ 146) fits the 160 reserve (test `outer_text_fits_reserve`). Only stages too short for art + text even at `CENTER_H_MIN` set `h_text_budget = 0`, in which case every slot goes art-only rather than reach the rail. The in-slot text reserve (160) covers the measured worst case (two-line 28px selected title + two 16px meta lines + Update badge ≈ 153, plus rounding slack) so the selection's badge never clips at the strip edge; `H_ROW_BREATHING_ROOM` shrinks equally (90 → 80, sum constant) so cover size holds. The freed ~140px would otherwise inflate every capsule (470 → 596px at 1080p, losing a visible neighbor per side), so `H_ROW_BREATHING_ROOM` holds cover size steady and turns that room into slack. Capsule fill is transparent (`strip_capsule`): the slot fade rides on the art, so an opaque `CONTENT` card underneath made faded neighbors read as grey plates instead of dissolving into the backdrop. Do-not-regress on all of it (tests `horizontal_art_shares_one_centerline`, `horizontal_arc_sags_below_centerline`, `h_arc_grows_with_distance`, `every_slot_carries_the_same_text_budget`, `horizontal_capsule_size_is_stable_across_resolutions`, `in_slot_title_follows_art_by_one_gap`, `outer_peek_titles_would_overlap_at_neighbor_wrap`, `text_reserve_growth_holds_capsule_size`, `horizontal_block_lead_drops_art_row_without_eating_rail_gap`).

**Transition nav policy:** overlay/chrome transitions (controllers-surface open/close, strip scroll, settings drawer, position bar, chrome status rail) stay cancellable and never block nav; transitions that reflow main content (immersive horizontal↔vertical layout transition, 300ms) block pad + keyboard nav for their duration. Mechanism: `State::animating()` gates pad nav (surface/enter-phase; the strip scroll deliberately ignored as retargetable), `overlay_blocking()` gates modal overlays, and `State::layout_transition_active()` is the transition-scoped gate shared by keyboard dispatch (`StartKeyAction::Up/Down/Left/Right`), the `MoveUp`/`MoveDown` arms, and settings focus/nudge — Confirm/Cancel/Close/settings-toggle/controllers-toggle stay live throughout, as do deliberate settings commits (open-menu Confirm picks, mouse Set* writes); only focus moves and slider nudges freeze mid-transition. **Style:** directional slide+fade along each layout's scroll axis (vertical exits up / enters from below, horizontal exits left / enters from the right), ~72px peak with a full fade at the midpoint swap; per-item FLIP was skipped because the two orientations use different metrics/neighbor counts/item shapes in different parent containers, so rect interpolation would duplicate layout math and risk jank.

**Position rail (navbar) visibility:** the immersive games-list position rail ([`position.rs`](../src/ui/start/position.rs)) auto-hides after `HIDE_AFTER_MS` (2s) idle, then slides out over `FADE_MS` (opacity leads over `OPACITY_MS`). Pref `start_screen_navbar` (`NavbarVisibility`: `when_navigating` default, `always_on`; Start settings drawer → Immersive → Navbar) pins the rail: while `State::navbar_pinned` the show path stays (1, 1), `position_bar_motion()` reports no in-flight hide, and the `tick_anim` hide timer is skipped. The shell syncs the pin from prefs on Start open, every `StartFrame`, on every service snapshot, and immediately in `apply_start_screen_navbar` (which also closes the dropdown menu like the layout apply). No IPC bump: prefs travel whole-struct over IPC with `#[serde(default)]`, and protocol 1 already covers the break. Show triggers re-stamp `note_position_bar_scroll` after the open-path clears (`reset_to_games` / transition-phase begin): `StartOpened` (covers warm opens and refreshes the cold hide clock to visible time) and cold-load begin. `cycle_games_sort` re-shows (it is the only sort-mode writer; `refresh_start_rows` only mirrors prefs), and `set_rows` re-shows on a play-key order change (Steam-scan reorder). All triggers are no-ops under `AlwaysOn` (pinned (1, 1), hide timer skipped) and only start the chase under reduced motion (slide snaps via a 0 movement duration while opacity still eases).
